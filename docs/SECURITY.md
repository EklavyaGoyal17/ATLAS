# Security and privacy

Educational local deployment only. Compose publishes ports on 127.0.0.1. Native API binds loopback unless explicitly overridden. nginx is a same-origin API proxy. TLS and per-user authorization are required before any remote/shared deployment; this version must not be exposed publicly.

Bearer authentication is stateless and constant-time compares the configured token. No session cookies or HTTP Basic, so CSRF is disabled intentionally. The API rejects missing/incorrect credentials. Token length is checked at startup. The example token is public, for local use only. Console holds the token in memory and clears data on disconnect; never include it in URLs. Do not log headers or bodies. JSON logs include generated correlation IDs, method, status and duration; audit events associate successful business changes with those IDs.

Only synthetic merchant IDs, bounded integers, explicit currencies, and restricted idempotency keys are accepted. No PAN/CVV fields exist. Unknown JSON properties and fractional integer coercions are rejected. Authenticated JSON bodies, including streamed bodies, are capped at 16 KiB before parsing. Database lock/statement timeouts bound contention. SQL values are bound parameters. Internal errors hide SQL/stack details from clients; logs retain exception type and source frames without exception messages or SQL. Approved repository snapshots are read-only and bounded. Source never executes during indexing. Optional model transmission requires context preview and explicit matching source-ID consent; there are no model file/command tools. The process-wide local identity budget allows a burst of 120 and refills at 60 requests/second; it is not a distributed quota.

Credentials come from environment configuration; `.env` is ignored. Database administrator access can bypass application rules, so do not treat paired postings as protection against a malicious database administrator. There is one authorized local engineer role, not multi-tenant authorization. The API container runs as a non-root user. The local database's atlas initialization/owning role is powerful; separate runtime, migration and administrator roles before any shared deployment.

Engineering records and payments stay in PostgreSQL. Record deletion cascades its revisions; metadata-only audit survives. Documents are limited to 1000 with at most 20 revisions each and a paginated 200-record listing. Repository snapshots and telemetry live only in process memory and can be cleared/restarted. No automatic lifetime deletion of financial/outbox evidence exists. Stop services and deliberately manage the named volume for full deletion; this is irreversible and must be approved by the operator. Backups contain synthetic records and should still be kept private. Tests use a separate database with an explicit name guard before truncation.

Before shared deployment: replace the token with OIDC and least-privilege identities; configure TLS, secret management, distributed identity-scoped rate limits, slow-client connection timeouts, audit access controls, backup restore drills, and continuing vulnerability remediation. Hosted CI has passed npm audit, source/runtime-image vulnerability gates, Compose browser tests and restart recovery. A network-isolated synthetic logical restore drill is also verified; actual application-data restoration remains operator-controlled. Local scanning identified and remediated managed Java dependency and Alpine package findings. The final source graph and both app images report zero High/Critical findings; npm audit reports zero known frontend findings. [DEPENDENCY_REVIEW](DEPENDENCY_REVIEW.md) records scope and patch decisions. These checks are not certification or proof of absence of vulnerabilities.

Worker controls require the same local engineer token. New fault scenarios are fixed enums, not arbitrary code or destinations. The durable worker sink is a local PostgreSQL archive. A separate signed loopback HTTP webhook demo accepts no destination URL, uses timestamp/HMAC checks and deduplicates immutable outbox envelopes. The demonstration reuses the local bearer key for signing; separate keys are required before external delivery. Step controls are deliberately not request-idempotent and have no autonomous command execution. The worker is paused initially; its saved running setting resumes after restart. Inbox and notification writes are atomic, but external side-effect atomicity is not claimed.

Repository import and model controls are implemented and tested: approved-root checks, no-follow bounded reads, safe extensions, traversal/link rejection, heuristic redaction and instruction-like context exclusion. Fixed Git builtins have no shell, pager, external diff, text conversion or fsmonitor; bounded history/diff are the only subprocesses. Maven XML external entities are disabled. The source snapshot can be stale, and hostile concurrent filesystem replacement is not fully eliminated by portable checks. Use an operator-controlled stable checkout. See AI_AND_IMPORT and ADR 008.

Never record employer code, credentials, production logs, proprietary design, internal incidents or customer information in the engineering journal. The journal explicitly requires a non-confidential note acknowledgement and its bodies are excluded from assistant retrieval. Exported notes and database backups have their own retention; deleting the live record does not delete earlier exports/backups. Heuristic masking and instruction detection are not complete security guarantees.
