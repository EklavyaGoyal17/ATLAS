# Original requirement to implementation map

This is an independently built educational project, without American Express affiliation. Synthetic money and incidents must never be described as live financial processing. Tests and measured results are in TESTING; limitations are part of acceptance.

| Requested area | Concrete implementation | Demonstration / evidence | Limits |
|---|---|---|---|
| Repository intelligence | `RepositoryIndex`, `GitHubRepositoryImport`, `RepositoryMetadata`, `RepositoryArchitecture`, `RepositoryImpact`; approved local/public GitHub snapshots, commit provenance, extension inventory with source links, bounded npm/Maven/Python/Go declarations, broader searchable formats, Java AST, source-linked cycles/coupling/impact, potential calls and local Git evidence | Demo 4 and GITHUB_IMPORT; URL/redirect/ZIP/transport/publication/security checks, snapshot/report/field budgets, local deadline/cancellation/publication races, redaction deadlines, independent cycle/distance oracles, source/export/consent/reimport browser flows and separate public download smoke script | Structured Java syntax only; other languages remain indexed text with conservative manifests. No compiler/runtime proof, grade, package installation or automatic test selection. Unsupported resolution skipped. Public GitHub default branch only; anonymous limits apply, no private/enterprise or imported execution. Graph/archive/path budgets explicit; local checkout stability required |
| Payment systems | `payments/PaymentService`, `PaymentStore`, V1 constraints, immutable idempotent responses, integer/currency rules, paired capture/refund postings and reconciliation | Demo 1; PaymentIntegrationTest, PaymentRulesTest, RefundPropertiesTest, lifecycle browser flows | One fictional merchant; no settlement, actual funds, expiry, FX or real payment credentials |
| Async recovery / webhooks | `eventing/OutboxPublisher`, `DeliveryService`, scheduler, fencing and inbox; `LocalWebhooks` signed loopback HTTP receiver with receipt deduplication | Demo 2, DeliveryIntegrationTest, EngineeringIntegrationTest, recovery-check.mjs | Durable worker's sink is the local notification archive; webhook demo is a separate real HTTP boundary. No arbitrary external destinations/broker |
| Distributed concepts | Twelve `SimulationEngine` recipes plus the real worker: saga compensation, breaker, rate budget, bulkhead, cache invalidation, optimistic/pessimistic locks, eventual consistency, lost responses, corrupted ledger model, SLO budget and timeout policy | Systems lab model selector; SimulationEngineTest checks determinism/invariants for 100 seeds per recipe | Discrete-event models are labeled synthetic. They do not establish actual distributed infrastructure or production capacity |
| Observability | OTel SDK local exporter, W3C HTTP propagation, HTTP/JDBC spans, structured log correlation, measured percentiles/counters, health, actual queue/retry/dead counts | Demo 3, TelemetryTest and shared HTTP/JDBC trace integration test | 1000 spans/500 latency samples in memory; resets on JVM restart; no external collector |
| Incident response | Eight baseline/affected recipes; real isolated Hikari/PostgreSQL exhaustion/recovery; durable bounded sample spans; paged reopen/filter/export and postmortems | Archive atomicity/bounds/access/deletion, legacy migration, browser reload, actual JVM restart and isolated logical restore | At most 128 spans/128000 bytes per investigation; older records lack expired spans. Query/lock/pool work is real; deadlines/queue use controlled local workload |
| Grounded assistant | Cited local declarations/potential calls, conditional investigation/test/review steps, conservative lexical retrieval, optional HTTPS/local bridge, question/snapshot/context-bound approval, no execution tools | Demo 5; prompt injection, redaction, consent invalidation, fact citation bounds, stale browser responses and stub transport tests | Suggested tests need execution; static facts do not prove runtime paths. No model/key installed; live quality unverified. Citation identity is not semantic proof |
| System design | SVG editor, pointer/arrow-key movement, ten component categories, connections, responsibility/instance fields, assumptions, topology findings, six templates, version previews, SVG/JSON exports | Architecture browser workflow, optimistic document race/revision validation tests | 24 components, 48 connections, 12 KiB document; single-instance findings are heuristics, not measured reliability |
| Engineering growth | PostgreSQL journal/ADR/postmortem/learning/review records, required ADR fields, review dates, fourteen curriculum areas, file-linked exercises, evidence notes and rubric review | Growth browser workflow; document save/revision/delete tests | Self-reported progress and term coverage; no automated correctness grade or claim the user learned a concept |
| Security/privacy | Spring Security, memory-only browser token, fixed local identity, request budget and body limits, input/output boundaries, safe import, redaction, bounded subprocesses, metadata-only workspace audit, opt-in model transport, deletion and vulnerability gates | Original 17 required test categories mapped in TESTING, SECURITY and CI | Loopback deployment only; no shared auth/TLS/pen-test/compliance claim. Heuristic masking is imperfect |
| Delivery / performance | Compose, Flyway migrations, Java 21 runner, hosted CI, load scripts, health-gated console, process recovery, isolated logical restore, checksummed application-created backup opened by a restored API, API contract and exports | scripts/verify.ps1, scripts/restore-drill.mjs, scripts/application-backup-drill.mjs, scripts/load.mjs, scripts/workspace-load.mjs, five demos and hosted run evidence | Generated isolated backup acceptance; existing-user-workspace restoration, encrypted retention, broader capacity, HA and manual assistive-technology review remain operating work |

The optional/recommended stack is intentionally adapted: explicit JDBC replaces JPA; provisioned disposable PostgreSQL replaces Testcontainers lifecycle; native HTML/CSS/SVG controls replace Tailwind, a component framework and React Flow for bounded graphs; local OTel inspection replaces a Prometheus/Grafana cluster; lexical retrieval replaces a remote embedding/vector service. ADRs explain why. Kafka, Redis, microservices and Kubernetes are not needed to demonstrate these local boundaries.
