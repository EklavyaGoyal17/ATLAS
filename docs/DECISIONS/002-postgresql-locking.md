# ADR 002: Explicit PostgreSQL locking with JDBC
Context: duplicate requests and concurrent captures require cross-process serialization. Decision: transaction-scoped advisory locks for idempotency keys and row locks for payment updates, expressed with JDBC. Alternatives: process mutexes fail across instances; optimistic retries add teaching complexity; JPA hides SQL that is central to this lesson. Tradeoff: PostgreSQL portability over visible correctness. Consequences: real PostgreSQL tests are mandatory; JDBC mapping is hand-written. Review: before introducing another database or large aggregate.
