# ADR 013 — Approved public GitHub snapshots

Context: local-root import requires an operator mount and a prior checkout. Users also need to investigate public repositories by pasting a GitHub link, while keeping repository data separate from executable services and optional model transmission.

Decision: add a separately approved public GitHub source. Accept only canonical HTTPS `github.com/owner/repository` links, optional `.git` and trailing slash, and an optional exact relative source subdirectory. Reject credentials, ports, queries, fragments, encoded paths, branch paths and other hosts before any request. Private repositories and GitHub Enterprise are outside this adapter.

Read the default branch's latest commit through the anonymous commit-list API, then request the archive for that full SHA. The only accepted redirect is the expected HTTPS `codeload.github.com/owner/repository/legacy.zip/SHA` location. The HTTP client has no authenticator or cookies and never follows redirects automatically. It reads no Git configuration, credential helper, model key, local token or imported instructions. Requests carry only fixed public-client headers. GitHub refusal/rate limits, missing/private resources, invalid redirects and network failures become bounded domain errors.

Parse the ZIP entirely in memory. No checkout, temporary repository, archive extraction, Git hooks, submodule fetch, LFS download, package install or imported command occurs. Entry names must have one archive root and cannot be absolute, duplicate, backslash/drive paths, control characters or dot/parent components. Payloads are literal bytes, never link targets. Every entry is counted and drained through the expanded-byte budget, including skipped content. UTF-8 and NUL checks, hidden/generated/credential exclusions, redaction and the existing Java parser apply before publication. Supported non-Java text remains searchable without invented AST relationships.

Bounds: one public download at a time; 3-second connection, 10-second header/request and independent 10-second body deadlines per response; 128 KiB metadata, 16 MiB compressed archive, 32 MiB total expanded archive, 5000 entries, depth 18 after the archive root and a 15-second archive-processing deadline. Indexed source remains at most 500 files, 4000000 bytes total and 160000 bytes per file. Oversized, invalid UTF-8 and NUL-containing supported files are omitted with bounded count summaries. A source scope can reduce indexed content, but it cannot reduce the whole-archive limits.

Publication is atomic: capture the index revision before downloading; deletion or a successful replacement increments it. A stale download returns `IMPORT_SUPERSEDED` without publishing or auditing a new approval. Failed imports leave the last approved snapshot intact. A successful audit precedes replacing the snapshot. Origin metadata records source kind, canonical URL, full commit and scope. Local imports retain ordinary bounded Git inspection; remote archives explicitly have commit provenance but no downloaded history or local diff. Sources remain in memory and are cleared on deletion or JVM restart.

The console separates local and GitHub consent, resets approval on input edits and disables competing import/delete controls during a request. Intent guards discard responses after navigation/unmount. No import implicitly authorizes an AI request. Exported/source-linked evidence carries the immutable snapshot identity.

Alternatives: cloning invokes Git's transport and workstation credential/configuration boundary and writes an untrusted checkout. Unrestricted archive URLs or automatic redirects create an unnecessary destination boundary. Fetching each source blob separately consumes many anonymous API requests. The bounded GitHub archive adapter keeps one explicit source boundary and needs no extra dependency or user API key.

Validation: controlled network/ZIP fixtures cover host/path/redirect rejection, pinning/scopes, expanded and indexed bounds, malformed/duplicate entries, redaction, errors, concurrency and supersession. Transport tests cover absent credentials/cookies, disabled redirects, body limits and deadline cleanup. Browser fixtures test consent, provenance and late-response state without pretending to download GitHub. A separate operator smoke check exercises actual public repositories; TESTING records executed results.

Review date: 2027-01-19, or before adding credentials, enterprise hosts, arbitrary URLs, branch selection or imported execution.
