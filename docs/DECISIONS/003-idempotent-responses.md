# ADR 003: Persist the original command response
Context: HTTP delivery can fail after a successful commit. Decision: store a canonical payload fingerprint and serialized response in the business transaction under merchant/key. Alternatives: recomputing current state on replay changes the original answer; reserving keys separately can leave stuck commands. Tradeoff: permanent records and response schema migration costs. Consequences: replay returns the original payment version, even after capture; clients refresh detail for current state. No expiration yet. Review: before retention or API version changes.
